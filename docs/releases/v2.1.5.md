## Unreached v2.1.5 — Release & Operations Automation Hardening

Version 2.1.5 is a **release and operations automation hardening maintenance release** on the certified 2.1 line. It does not change the user-facing comprehension-first product, mission-data semantics, prayer behavior, privacy model, private-sync contract, provider boundary, or redistribution policy.

### Generic exact-SHA publication

- Replaces the per-version `publish-vX.Y.Z.yml` lifecycle with a single version-agnostic release publisher.
- The publisher reads the release version directly from the exact candidate SHA's `package.json`.
- The matching tag is derived as `v<package version>` and the matching release-note file must exist at `docs/releases/v<package version>.md`.
- Existing tags are never moved. If the derived tag already exists at a different SHA, publication fails closed.
- Existing matching releases are treated idempotently only when tag identity is already correct.
- Publication continues to wait for the same complete exact-SHA evidence set before creating a tag or GitHub Release.

### Scheduled release-truth monitoring

The six-hour `Unreached Operations Health` workflow now verifies not only service availability but also release identity:

- the version in `package.json`;
- the latest non-draft, non-prerelease GitHub Release;
- the corresponding Git tag;
- the exact target SHA of both tag and release;
- the required production statuses `unreached/pages-production`, `unreached/peoplegroups-live`, and `unreached/worker-production`.

This catches a class of operational drift that uptime-only monitoring could miss: a healthy deployed application whose repository version, release tag, published release, or production evidence no longer agree.

### Static policy hardening

- Phase 4 now requires the release-truth monitoring markers in the scheduled operations workflow.
- Phase 5 now requires the generic publisher and rejects legacy version-pinned publication workflows.
- Release checks require v2.1.5 release metadata and documentation while preserving the existing privacy, source, attribution, and licensing assertions.

### Preserved product behavior

All v2.1.4 comprehension-first behavior remains unchanged, including:

- meaning → evidence → context → prayer → research hierarchy;
- plain-language unreached explanation before exact GSEC detail;
- four essential facts on people profiles;
- direct `Pray today` entry;
- technical source information behind progressive disclosure;
- represented-population and map-denominator caveats;
- PeopleGroups.org source-native mission/resource semantics;
- local-only default and explicit opt-in private continuity;
- no public static PeopleGroups corpus mirror.

### Human acceptance boundary

The optional five-person U11-H observational protocol was explicitly waived on 31 August 2026 and is not represented as passed. Automated U11 and release certification remain valid; no fabricated human-comprehension result is claimed.

### Governance boundary

GitHub repository administration still reports `main` as unprotected at the time of this release. Branch/ruleset protection remains tracked separately as repository administration work and is not simulated in application code.
