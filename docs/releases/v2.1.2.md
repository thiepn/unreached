## Unreached v2.1.2 — Loading-Latency Maintenance

Version 2.1.2 is a maintenance performance patch on the certified 2.1 line. It does not expand product scope, change mission-data classification, change prayer behavior, broaden persistence, or alter provider redistribution policy.

### Loading improvements

- Starts prepared PeopleGroups IndexedDB hydration immediately when the application entry module runs instead of waiting for an idle callback or fallback timer.
- Keeps startup hydration local-only; warming the prepared snapshot does not itself request PeopleGroups.org.
- Adds DNS/preconnect hints for PeopleGroups.org so connection setup can begin earlier.
- Preloads only the exact top-level lazy route indicated by pointer or keyboard navigation intent.
- Allows a true cold People Explorer to become searchable/filterable after the first validated provider page arrives while the remaining pages continue loading.
- Explicitly labels that cold state as a partial catalog and makes its search/filter/match counts temporary.
- Keeps guided starts and all map/country/language/prayer aggregate semantics gated on the complete validated corpus.
- Never persists a partial provider response as the complete prepared snapshot and discards the preview if the full corpus fails.

### Performance and acceptance integrity

- Retains provider fetch concurrency at six pending a separate provider-safe benchmark.
- Keeps the existing prepared full-corpus search budget under 4× Chromium CPU throttling.
- Separates prepared-search latency certification from network arrival time for records not yet present in a partial cold catalog.
- Makes cached/refreshing runtime-state browser assertions responsive-safe without requiring compact mobile layouts to display the desktop status badge.
- Preserves the existing deterministic 12,370-record search/index benchmarks and full browser/device-class matrix.

### Data, privacy and licensing boundary

- PeopleGroups.org / IMB Global Research remains the active runtime mission-data provider.
- GSEC 0–3 remains `unreached`, GSEC 4–6 remains `other`, and missing GSEC remains `unknown`.
- No public static PeopleGroups corpus mirror is added.
- Local-only use remains the default and optional private continuity remains explicitly opt-in.
- No browsing history, prayer-history/performance data, PeopleGroups corpus data, analytics or advertising data is added to private sync.
- Existing project licensing and third-party source notices remain unchanged.

### Certification

Release publication remains exact-SHA gated and requires:

- deterministic build and Phase 1–5 policy gates;
- dependency vulnerability/license audit;
- full Chromium, Firefox, WebKit, mobile Chromium and mobile WebKit certification;
- PeopleGroups live corpus/CORS/editorial certification;
- GitHub Pages deployment and canonical production browser certification;
- deployed private Worker health/security/CORS/Access certification;
- successful production commit statuses for Pages, PeopleGroups and Worker production.

### Acceptance boundary

Automated mobile acceptance continues to use Pixel 7 Chromium and iPhone 15 WebKit device emulation with touch. This execution environment has no connected physical iOS/Android hardware or external real-device testing provider, so the release does **not** claim physical-hardware testing.

GitHub repository administration previously reported `main` without branch protection. This maintenance release preserves CODEOWNERS and exact-SHA publication gates but does not claim repository protection that GitHub does not report.
