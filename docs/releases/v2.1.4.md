## Unreached v2.1.4 — Comprehension-First UX Maintenance

Version 2.1.4 is a **comprehension UX maintenance release** on the certified 2.1 line. It does not change the underlying mission-data classification, introduce new provider-derived claims, broaden private persistence, alter prayer-history policy, or change the PeopleGroups.org redistribution boundary. It reorganizes the existing product so human meaning and prayer are easier to reach without removing research depth.

### Comprehension-first people profiles

- People profiles now follow **meaning → evidence → context → prayer → research**.
- PEID, PGID and GSEC no longer compete with identity and human context in the hero.
- A dedicated status explanation tells users why a record is marked unreached before the exact GSEC code is exposed.
- The primary overview is limited to four essential facts: population estimate, primary religion, primary language and Bible resource status.
- Exact source identifiers, GSEC, taxonomy, timestamps, provider labels and methodology remain available through detailed research disclosures.
- Prayer is promoted to a first-class action without inventing person-specific prayer claims.

### Country and people discovery

- Country profiles now begin with exactly three understandable metrics and explicitly distinguish represented population from national census population.
- The largest represented unreached peoples appear before technical country tables.
- Country, language and religion are normal people-explorer filters rather than buried research controls.
- People cards no longer expose PEID, PGID or GSEC; those values remain available on the detailed profile.

### Explore map and first-minute entry

- The default map is presented as **Unreached population share** with an explicit non-census denominator caveat.
- The second mission view remains **Unreached people-group share**.
- Mission-status coverage, population-data coverage and source-record counts remain available but are clearly treated as research views behind **Change map view**.
- Existing certified layer IDs and URL-state compatibility are unchanged.
- Explore now exposes **What does “unreached” mean?** directly. The first explanation uses ordinary language before exposing the GSEC 0–3 implementation detail.
- Explore also exposes a direct **Pray today** path on desktop and mobile.
- Short desktop viewports compact non-essential explanatory chrome so the country browser remains contained and usable.

### Preserved v2.1.2 and v2.1.3 behavior

- Prepared PeopleGroups IndexedDB hydration still starts immediately.
- Provider connection and top-level route prewarming remain opportunistic and bounded.
- A true cold People Explorer may become searchable from validated partial provider pages, with explicit incomplete-catalog labeling.
- Map, country, language and prayer aggregates still require the complete validated corpus.
- Partial provider data is never persisted as a complete prepared snapshot.
- The v2.1.3 narrow Explore methodology layout correction remains in normal flow and does not widen the page.

### Data, privacy and licensing boundary

- PeopleGroups.org / IMB Global Research remains the active runtime mission-data provider.
- GSEC 0–3 remains `unreached`, GSEC 4–6 remains `other`, and missing GSEC remains `unknown`.
- Categorical evangelical-presence values are not converted into invented percentages.
- Bible availability labels are not converted into invented translation-completeness milestones.
- Represented population is not described as national census population.
- No public static PeopleGroups corpus mirror is added.
- Local-only use remains the default and optional private continuity remains explicitly opt-in.
- Existing project licensing and third-party source notices remain unchanged.

### Certification

Release publication remains exact-SHA gated and requires deterministic CI, dependency vulnerability/license audit, full desktop/mobile browser certification, PeopleGroups live certification, GitHub Pages deployment plus canonical production certification, Worker production certification, and successful Pages/PeopleGroups/Worker production commit statuses.

The automated browser suite includes the comprehension-first profile/map/country contracts and a first-minute entry path that verifies users can reveal the plain-language unreached explanation and reach **Pray today** without first opening technical source detail.

### Human acceptance boundary

Automated tests certify structure, navigation, disclosure, accessibility mechanics, source-truth preservation and browser behavior. They do not prove that real newcomers understand the product. The repository therefore keeps a separate five-person observational protocol in `docs/U11_FIRST_MINUTE_ACCEPTANCE.md` and does not claim that human result until it is actually observed.

Automated mobile acceptance continues to use Pixel 7 Chromium and iPhone 15 WebKit device emulation with touch. This execution environment has no connected physical iOS/Android hardware or external real-device testing provider, so the release does **not** claim physical-hardware testing.

GitHub repository administration reports `main` without branch protection. This maintenance release preserves CODEOWNERS and exact-SHA publication gates but does not claim branch protection that GitHub does not report.
