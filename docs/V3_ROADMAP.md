**Status:** Scope-frozen roadmap closed by Phase 20 Peak Certification  
**Rule:** Phases 0–12 produce Unreached 3.0. Phases 13–20 are the finite post-3.0 peak-system expansion. Phase 20 closes the numbered V3 roadmap.

## Hard gates

### Gate A — before Phase 4

Phases 1–3 must resolve:

- the canonical V3 source strategy;
- normalized product entities and provenance;
- editorial tiers and citation rules.

Visual redesign must not encode unresolved data semantics.

### Gate B — before Phase 8

The visual foundation, shell, Explore, and geographic hierarchy must be stable enough that the people profile is designed inside the final V3 system rather than another temporary shell.

### Gate C — before Phase 12

Explore, geographic navigation, people profiles, search, prayer, Saved, mobile behavior, source truth, and accessibility must all work coherently. Content expansion must not be used to hide broken product journeys.

### Gate D — before Phase 13

Unreached 3.0 must be release-quality and shipped. Post-3.0 ideas are not allowed to delay or destabilize the focused atlas release.

---

## Scope discipline

Every implementation task must map to the active phase acceptance criteria.

If an idea does not belong to the current phase:

1. record it in the relevant later phase;
2. do not implement it early unless it is a blocker;
3. do not create a new public roadmap phase for it.

Internal engineering substeps are allowed, but the roadmap remains these 21 phases (`0` through `20`).

After Phase 20, ordinary maintenance, content growth, source refreshes and bug fixes do not create Phase 21+. A genuinely new architecture-level product capability requires an explicit reviewed architecture decision and corresponding lock update.

---

## Product priority order

When trade-offs are required, optimize in this order:

1. factual/source correctness;
2. human understanding;
3. geographic and editorial usefulness;
4. prayer usefulness;
5. accessibility and reliability;
6. performance;
7. visual refinement;
8. optional power/research features.

A technically impressive feature that weakens the normal Discover → Understand → See the need → Pray → Remember loop should not ship.
